spec‑flow — a deliberately small moai‑adk

Porting the useful 20% of MoAI‑ADK's harness onto opencode's native agents, skills and commands.

status: accepted phase 1: implemented — T‑019 phase 2: planned — T‑027 scope: project‑local 2026‑08‑28

MoAI‑ADK is a 4,400‑commit Go binary that wraps Claude Code with 12 agents, 18+ skills, an MCP server, a web console, multi‑LLM cost routing and a five‑column multi‑terminal Kanban board. Most of that machinery works around limitations opencode does not have. What is genuinely worth stealing fits in one PowerShell script, two skills, one command and a config file. Phase 1 of that is now in this repo and verified against a real build.

01What MoAI‑ADK actually is

Two products share the name. The Python line (PyPI moai-adk v1.14.5) was 20 agents + 52 skills, EARS specs, DDD cycles and LSP‑driven autonomous loops. The current Go line (modu-ai/moai-adk v3.1.3) is a rewrite: a single binary that installs a .claude/ + .moai/ scaffold and drives Claude Code from outside. The design below borrows the spine of v3 and the vocabulary of v1.

The spine

/moai plan "Add JWT login" → authors SPEC‑AUTH‑001 (GEARS/EARS requirements + acceptance criteria) ↓ plan-auditor → an independent agent audits the SPEC. PASS → run. DEBT → back to plan. ↓ /moai run SPEC-AUTH-001 → TDD (RED→GREEN→REFACTOR) or DDD (ANALYZE→PRESERVE→IMPROVE) ↓ trust-but-verify → orchestrator re-runs the checks itself; agent claims are not trusted ↓ sync-auditor → scores Functionality 40 / Security 25 / Craft 20 / Consistency 15 ↓ /moai sync SPEC-AUTH-001 → docs, CHANGELOG, conventional commit, PR

The five ideas underneath it

IdeaWhat it means in practice
Verification‑claim integrity"tests pass" must be bound to the command actually run and its output. You may not present an unrun check as success, nor pass off a stale measurement as fresh. Enforced through a mandatory 5‑section report: Claim · Evidence · Baseline attribution · Gaps · Residual risk.
Author ≠ auditormanager-spec writes the SPEC; plan-auditor grades it. manager-develop writes code; sync-auditor grades it. The writing side never grades its own work.
TRUST 5 gateTested · Readable · Unified · Secured · Trackable. One command runs lint + format + types + tests. Their bar: ≥85% coverage, 0 lint errors, 0 type errors, conventional commits.
Long‑horizon continuityWork survives /clear because state lives on disk: progress.md per unit of work, handoff messages, decision memory.
Context isolationKanban Mode splits one task across four hand‑launched terminals (lead + plan + run + sync) so no session carries three phases of history. Factory Mode runs N such lanes in parallel worktrees.

And the machinery around it

A 12‑agent catalog with per‑agent model×effort cells; a self‑hosted MCP server exposing 21 tools; moai web with 6 screens and 11 settings tabs; Claude‑leader/GLM‑worker routing claiming 60–70% savings; marker‑based detection for 16 languages; an @MX/@NAV tag graph building nav-graph.json; a goal engine with turn limits, stagnation guards and wall‑clock budgets; an append‑only JSONL "Origin‑Trail Chain" tracking worktree ancestry; a self‑improvement loop promoting observed failures into proposed rule changes.

Read the incentives. The README pushes a z.ai GLM referral link in three places and states that sign‑up rewards fund the project. That does not make the engineering wrong, but a meaningful share of the design — CG mode, multi‑LLM routing, the whole tokenomics chapter — solves a cost problem partly created by running 12 agents where 4 would do.

02Keep / drop

Keep — carries the value

  • plan → run → sync. Forcing a written spec before code is the highest‑leverage habit in the system. phase 2
  • Author ≠ auditor. A second agent with fresh context and no stake catches what the writer structurally cannot. The one place extra agents genuinely pay. phase 2
  • Evidence‑bound claims. Costs nothing, attacks the failure mode you actually hit: an agent asserting green tests it never ran. shipped
  • One gate command. A single entry point that builds, tests and checks format, whose raw output is the evidence. shipped
  • On‑disk progress. State that survives compaction. phase 2

Drop — cost without return here

  • Kanban / Factory / worktrees. Four terminals exist to give each phase a clean context. opencode's task tool already spawns subagents in isolated child sessions. solved natively
  • MCP server + web console. 21 tools and 6 screens of surface to maintain.
  • Multi‑LLM cost routing. opencode sets model per agent in one line of frontmatter.
  • 16‑language auto‑detection. This repo is CMake + C++23 + MSVC. One toolchain, hardcoded.
  • @MX / Navigator graph. A second index to keep in sync with the code.
  • Goal engine, self‑improvement loop, decision memory, Origin‑Trail Chain. Problems you do not have yet.
  • 20 agents / 52 skills. Every agent is context the model weighs before acting. A large catalog degrades routing accuracy.

The important row is Kanban Mode. MoAI‑ADK's flagship v3.1 feature — four terminals, a run‑id, a lead that may only advance cards on evidence it read because "inter‑session delivery is not guaranteed" — is an elaborate workaround for one thing: Claude Code's main session accumulating all three phases of context. opencode's task tool gives each subagent a fresh window and returns one message to the parent. You get the context hygiene without the terminals, run‑ids, heartbeats or lineage tree.

04The real gate measured, not guessed

The first draft of this proposal guessed cmake --preset + ctest --preset. Both are wrong for this repo. What follows was established by running it.

What the investigation found

AssumptionReality
ctest runs the testsctest does not work at all. No enable_testing() or add_test() in CMakeLists.txt. Tests are doctest cases compiled into the application and run with test.exe --test.
cmake --build --preset x64-debugFails. CMakePresets.json declares configure presets only — no buildPresets, no testPresets. Must use cmake --build out/build/x64-debug.
cmake / clang‑format on PATHNeither is. Both ship inside Visual Studio. Located via vswhere.exe; cl.exe additionally needs the VS developer environment (Enter-VsDevShell) for INCLUDE/LIB.
Exit 0 means tests passedNot sufficient. test/mvp_gaps_test.h marks 4 known MVP gaps with doctest may_fail. They print ERROR:, then Allowed to fail so marking it as not failed, and the run still exits 0. The doctest summary lines must be read.
Format is a clean gate44 of 80 tracked files under src/ and test/ fail the newly added .clang-format. A repo‑wide check fails on day one, so the gate defaults to changed files only.
clang‑tidy is availableBinary exists, but there is no .clang-tidy and no compile_commands.json. Not in the gate — claiming static analysis ran would be a false claim.

Verified baseline — 2026‑08‑28, x64‑debug

$ pwsh -File scripts/gate.ps1

=== GATE SUMMARY ==================================================
PASS   configure  exit 0    skipped: CMakeCache.txt present
PASS   build      exit 0    0 first-party warning(s)
PASS   test       exit 0    [doctest] test cases: 22 | 22 passed | 0 failed | 0 skipped

GATE: FAIL (format)

That FAIL is correct. src/main.cpp is the only file modified in the working tree and it does not conform to the .clang-format that was just added. The gate found a real finding on its first run against real code — which is the entire point.

Design notes

  • The script is the gate, not the prose. MoAI‑ADK describes its gate in agent instructions, which means every run reassembles it from natural language and drifts. gate.ps1 is one command with a deterministic output format. The skill tells the agent to run it and explicitly forbids hand‑rolled substitutes.
  • Format scope defaults to changed files. -Scope Branch widens to the merge‑base with origin/main for PR time; -Scope All exists purely to audit the 44‑file debt (T‑021). This keeps the gate green‑able today without pretending the debt is gone.
  • Build warnings are filtered to first‑party code. Warnings from external/ (glfw, imgui, glaze, libpqxx) are noise you cannot fix.
  • The may_fail count is reported explicitly. A change in that number is a signal — either a gap closed, or someone deleted a marker.
  • No agents in Phase 1. Zero new subagents, zero model routing. The evidence discipline is testable on its own before the SPEC ceremony is added.

Using it

# in opencode
/gate
/gate -Scope Branch

# directly
pwsh -File scripts/gate.ps1
pwsh -File scripts/gate.ps1 -SkipFormat      # fast build+test loop
pwsh -File scripts/gate.ps1 -Reconfigure     # after editing CMakeLists.txt
pwsh -File scripts/gate.ps1 -Clean           # ~10 min, rebuilds vendored deps
pwsh -File scripts/gate.ps1 -Scope All       # audit format debt; expected to fail

06Phase 2 design T‑027, not yet built

One SPEC per feature branch, per the decision on record.

.opencode/
  agent/
    spec-auditor.md      subagent · edit:deny · grades a SPEC it did not write
    verifier.md          subagent · edit:deny · runs gate.ps1, writes the evidence report
  command/
    plan.md              /plan "<description>"  → author + independently audit a SPEC
    run.md               /run                    → implement the current branch's SPEC
  skills/
    spec-format/SKILL.md EARS-lite template, acceptance-criteria rules, S/M/L tiers

.spec/
  spec.md                one per feature branch. Merged selectively into main.
  progress.md            append-only: what ran, what it printed, what is left
git switch -c feat/tls-timeout you /plan handshake should time out after 30s instead of hanging ├─ @explore locates the code; does not guess at current behaviour ├─ writes .spec/spec.md (Tier M, 4 requirements, 3 acceptance criteria) ├─ @spec-auditor DEBT — "A2 names no verifying command" │ — "R3 'promptly' is ambiguous" ├─ fixes both └─ @spec-auditor PASS → 90 seconds. No code written. you /run ├─ writes failing tests from the acceptance criteria, pastes the failure output ├─ implements ├─ @verifier runs gate.ps1 itself — the implementer's word does not count │ build exit 0 · test 25/25 · format exit 0 │ Gaps: clang-tidy not run (T-023) │ Residual risk: no test for timeout during renegotiation └─ appends the report to .spec/progress.md merge to main, keeping what is worth keeping from .spec/

The one non‑negotiable rule. The implementer may say "I ran the gate"; that is a claim. gate.ps1 produces the exit code and output; that is evidence. A SPEC advances only on evidence that was read. Everything else in this proposal is convenience — this is the part that changes outcomes.

07Limitations → tracker

Every limitation identified is now a task in docs/status/tracker.md.

IDLimitationPri
T‑020Clean‑build warning count never measured. The "0 new first‑party warnings" threshold is currently checked against incremental builds only, so already‑compiled translation units are not re‑examined.P1
T‑02144 of 80 tracked src/+test/ files fail clang-format. Until that is decided (bulk reformat vs. leave), the gate cannot run -Scope All.P1
T‑022Test headers are #included by hand in src/main.cpp. A new test/*_test.h that is not added there silently never runs, and nothing catches it.P1
T‑023No static analysis. Needs .clang-tidy + CMAKE_EXPORT_COMPILE_COMMANDS before it can become a gate step.P2
T‑024No coverage measurement, so no coverage threshold. MoAI‑ADK's 85% bar is not portable to MSVC without work.P2
T‑025The gate is advisory. Nothing prevents a commit that skipped it. A git pre-commit hook binds regardless of which agent — or human — is driving; an opencode plugin would only bind agents.P1
T‑026Model routing (opus‑5 ceiling / sonnet floor) not wired — needs the exact provider model IDs confirmed.P2
T‑027Phase 2 itself: SPEC format, .spec/, /plan, /run, auditor + verifier agents.P1
T‑028Author≠auditor and "evidence, not claims" are conventions the primary agent must honour. They should live in docs/ai-instructions.md so they load in every session, not only in the command that happens to be invoked.P2
T‑029ctest is not wired. Decide whether to wire it or document the app‑binary invocation as permanent.P2

Known and accepted, not tracked

  • Restart required. opencode loads config once at startup. Editing a skill, command or agent needs a quit and relaunch.
  • Cost goes up in Phase 2. Two extra subagent round‑trips per SPEC. MoAI‑ADK's answer is cheap workers; ours is fewer agents. Whether the SPECs prevent enough rework to pay for it is a claim neither project has measured.
  • Windows‑only gate. gate.ps1 assumes MSVC and Visual Studio. The Linux/macOS presets exist in CMakePresets.json but are not covered.
